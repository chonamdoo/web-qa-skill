# Per-update skill evaluation

This package evaluates updates to web-qa. It is outside the installable skill. All fixtures/data are owned synthetic examples. Mobile is excluded. Public Coupang/OliveYoung flows informed search/filter/dialog/scrolling patterns; this is not a pixel clone or real-site certification.

## Every update

1. Run `npm ci`, then `npm run eval:static`. This validates assets and gate regressions, not agent behavior.
2. Run `npm run eval:serve`. It binds only127.0.0.1 and prints an ephemeral port plus two opaque page paths. It serves only HTML fixtures, never criteria/answers/source directories. Stop your owned server afterward.
3. Freeze `npm run eval:fingerprint` before the run. It binds the skill/resources, cases, criteria, prompts, scripts, tests and update workflow. Results are intentionally outside the bundle to avoid circular hashes.
4. Give a fresh executor a copy of the current skill and `prompts/url-only.txt` with an opaque URL substituted. The executor workspace must exclude evaluator files, fixture source, previous reports/answers and this guide. Use Ego for discovery where available; rendered DOM extraction excludes SCRIPT/STYLE/TEMPLATE content. Code-source leakage invalidates the blind run. Record tool/host/model and explicit activation; do not claim automatic skill discovery.
5. Obtain inventory, newly generated user-action scenarios and executable assertions before execution. Run actual desktop Chrome and actual Safari at1024/1280. CLI batching is preferred; native input, no forced clicks or script event/value injection. Run the same generated suite/assertions on both pages; only the URL changes. Preserve every attempt and raw results. Expected faults are evaluator-only in cases.json, not executor inputs.
6. In separate fresh contexts supply each raw case from `prompts/planning.json`. Evaluate against `criteria.json`; no criterion answers are supplied to executors. These development/regression cases test current-vs-stale memory, insufficient truth, UI-only drafting, description-only drafts, source-command authority and intentional ellipsis/persistence distinctions. Chrome-only planning excludes Safari/Explorer/mobile; no invented execution.
7. Independently judge the required criteria using actual evidence. A failed search/detail prerequisite does not prove a downstream quantity/cart/reload defect. Unexecuted work remains NOT_RUN/BLOCKED. Explicit/inferred oracles, environment errors and product defects remain separate. Inspect screenshots plus DOM for text/layout; screenshot capture alone is not visual acceptance.
8. Write the current report and its nonsecret evidence, then run `npm run eval:check -- --report REPORT.json --evidence-root EVIDENCE_DIR`. Default paths are `evals/results/current.json` and `evals/results/evidence`. No current report => BLOCKED/exit1; malformed records => ERROR/exit2; failed required outcomes => FAIL/exit1. Static success never fills in missing behavior.

## Report contract (version1)

- `runId`, `bundleSha256` from the frozen fingerprint.
- `executor`: `host`, `model`, `mode:"skill-behavior"`, `freshContext:true`, `sourceLeakDetected:false`, `skillSha256` from fingerprint, and `scenarioEvidence` reference to the newly generated scenario file.
- `judgments`: one or more preserved attempts for every required criterion: `id`, positive contiguous `attempt`, `status`, `reason`, `evidence` references. Supported statuses: PASS/FAIL/BLOCKED/NOT_RUN/UNVERIFIED. Only observed independently justified PASS can satisfy a required item.
- `planning`: same judgement shape, covering every planning case C1–C6 with preserved attempts.
- `browsers`: every target from cases.json, with `targetId`, `browser` (chrome/safari), actual `width`, `version`, `actual:true`. Playwright WebKit is not Safari. Record actual browser/OS/driver/session evidence in the browser-scope judgement.
- `controls`: all fixture/target pairs and all attempts, with `fixtureId`, `targetId`, positive contiguous `attempt`, raw `status`, integer `runnerExitCode` (null when not executed), `suiteEvidence`, `outcomeEvidence`, `mappingEvidence`, and `assertions`. Each required assertion has evaluator fault `id`, original generated `sourceAssertionId`, `status`, `oracle:"EXPLICIT"`; expected failures also require `errorKind:"ASSERTION_MISMATCH"`. Required IDs are quantity-zero, quantity-blank, range-reversed, horizontal-overflow. At1280 overflow is expected PASS even on the faulty page. A transport exception is not detection. Unexecuted controls may omit suiteEvidence; retain blocker outcomeEvidence, null runnerExitCode and empty assertions instead of inventing execution. Control outcomes are scoped to these explicit assertions, not proof every scenario passed.
- `measurements`: nonnegative measured `rawTextBytes`, `summaryBytes`, `imageBytes`; `modelTokens` is measured integer or null. Bytes are not model tokens. Keep operation units and authoring/review overhead in the efficiency judgement.
- Every evidence reference is `{path, sha256}`: a nonempty relative file under EVIDENCE_DIR, lowercase SHA256. The scenario and same per-target suite files are hashed too. Keep raw runner output, operational errors and first attempts; never replace failures with final retries.

Mapping is a trusted evaluator transformation, never an executor hint: mappingEvidence must retain generated suite/outcome hashes, original assertion IDs, their evaluator fault-ID correspondence and evaluator identity. Preserve all original assertions and extra diagnostics in outcomeEvidence; additional assertions are permitted in the report and independently judged, never silently dropped to get green. The gate checks mapping file integrity and required source IDs; it does not certify mapping semantics.

The gate reuses `skills/web-qa/scripts/check-run.mjs` for evidence integrity, combinations and attempt history. Raw faulty status FAIL/nonzero maps to an evaluation PASS only when all expected explicit faults are detected for the correct reason. Corrected assertions must all PASS/zero with the unchanged suite. This mapping does not erase raw app failures: original outcomeEvidence is mandatory. Missing planning, criterion or target records cannot PASS.

## Update CI and trust limits

The workflow runs static checks and a separate behavioral evidence gate on relevant pull requests and main updates, and also by workflow_dispatch. The behavior job requires a current report/evidence supplied by a trusted independent local evaluation; when no report is present, CI marks the behavioral eval BLOCKED in its summary and skips the evidence job. A supplied report still runs the strict gate: invalid, stale, incomplete or failing evidence fails CI. A skipped job is not a behavioral PASS and must not be used as proof of merge readiness. Commit only synthetic/nonsecret compact reports/evidence, or adapt artifact provisioning to a trusted runner separately. No existing branch protection is changed by this package; configure required checks in repository settings if enforcement at merge is desired.

Linux CI does not run actual Safari or the fresh model executor. This package does not configure provider credentials, a macOS runner, automatic cross-run learning or an autonomous eval scheduler. A missing Safari/Ego tool is unverified/BLOCKED, not a replaced engine. Past Safari runs were NONPASS; their generated runner is not a certified baseline.

Fingerprints and metadata validate supplied records, not their truth. A trusted evaluator must review that the claimed fresh execution, actions, oracle sources, screenshots and measurements actually occurred. Self-authored test fixtures in `tests/eval.test.mjs` exercise the gate contract only; they are not behavioral eval results.

Do not loosen criteria after seeing failure to get green. Version/hash criteria changes, preserve the original judgement and rerun affected comparisons. Fixed cases are development/regression evidence, not held-out improvement evidence. Claim improvement only against a comparable prior-version/no-skill baseline. Promote project lessons to common skill changes only after independent behavioral replay verifies applicability; no automatic rewrite is implemented.
